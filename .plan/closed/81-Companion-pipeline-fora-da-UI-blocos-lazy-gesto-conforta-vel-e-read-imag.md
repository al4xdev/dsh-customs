# Companion — responsiveness at stream end and opening existing history

## Direct request and initial evidence
The owner approved the appearance and operation of APK7, but reported UI lag when rendering/finalizing streaming, a small specific hitch when opening an existing conversation, back gesture too close to the screen edge; requested real lazy rendering in conversation, motion inspired by ha_app widgets/cards, and read_image images visible/clickable outside collapsed tooling.

Initial code inspection confirms: WebSocket onMessage enters viewModelScope Main and performs mux/follow/journal/publish; publish reconstructs TranscriptPresentation and RichTranscriptProjection over the entire history on Main; RichText can still perform static/final synchronous parsing and its MarkdownBlocks are Column/forEach; expanded ActivityGroup also composes entries via forEach. LazyColumn exists only at the outer level. Opening existing/new/config uses the same PremiumWorkspace tween, so the history load difference is a grounded hypothesis, not an FPS measurement. Readonly reference ha_app/src/styles/motion.css uses damped settle tied to scroll (+104,-7,+2.6,-.9,0), not different animations per conversation type.

## Authorized implementation
1. Remove heavy decoding/pure publishing from Main path in a **sequential and bounded** manner: do not reorder frames, do not conflate facts/protocol/approvals or invent completions. Conflate only replaceable presentation snapshots; workers/caches per session+generation, immutable state, stale results rejected, reset/logout cancels/discards. Native authority/facts/controller updates remain immediate upon admission. Do not launch parallel per-token parsing or run expensive synchronous flush on completion. Keep limits/UNKNOWN/stop/approval/send invariant. Error/overflow pipeline must safely rebaseline, not silently drop important frames.
2. Truly lazy rendering in stable units: project message/Markdown blocks and expanded activity entries to independent LazyColumn items, avoiding a huge response or 100 tools in a single Column. Prepare parse/plan off-UI with reuse bounded to current viewport window, without keeping transcripts in navigation cache12. Handle huge paragraphs with bounded units when necessary to avoid relayout of entire prefix per delta. Preserve semantics/order/native+derived IDs/folds/live→durable, selection/copy/safe links/code/tables/media/limits/notices. Human speech bubble remains coherent; controls and approvals never enter hidden lazy items. Opening empty/loading state does not clamp restored scroll position.
3. Opening existing history: prevent heavy parsing/hydration/composition from interrupting tween already approved for new/config. Coordinate ready presentation/transition, lazy preparation, and item motion without delaying RPCs/facts or using timers as proof of execution. Preserve draft/follow/manual/IME/restoration/cache and do not start animation on every token. Reference ha_app is readonly source only, without operating HA/network/deploy.
4. Gesture: widen the comfortable trigger region beyond the current narrow edge strip, with explicit axis-lock/slop/cancel/settle and arbitration. Do not hijack vertical pan, selection/longpress, horizontal code/tables, preview pinch/pan, composer/IME. Retain back button/system/accessibility navigation, 48dp target, and reduced motion support.
5. read_image: identify valid native result linked to admitted call; promote typed image references to visible rows at the associated chronological point (outside collapsed group, before subsequent prose when that is the real order). Do not decide based on raw name, prefix, JSON text, or arbitrary URL/file-path. Investigate actual readonly TUI/SDK format; if an envelope adapter is necessary, use recognized public contract with canonical tests/limits, without free base64 or authority bypass. Deduplicate promotion and detail by identity; click opens existing zoomable preview. Preserve admission+generation, thumbnail 768/preview 2048/bitmap 16MiB/LRU 24MiB 24 entries/concurrency 1, and no out-of-viewport fetches.

# Codex Resilience in DSH with Official Retry and Safe pi-ai Upgrade

## Objective
Recover observed 1000/1012 Codex transient disconnections for long agents without generic output replay or CLIENT tool duplication. Apply personal plugin and validated fork f5a24c to authorized main host, preserving sessions, versions, catalog, and rollback. Do not promise infinite continuity or exactly-once delivery for remote tools.

## Decided Architecture
- Local plugin `plugins/codex-transient-close/index.mjs` registered in dsh-tui profile, inject llm, public middleware `llm/stream` with prepend:true.
- Only openai-codex provider, calls tagged `isAgentLoopRequest` from same official dsh-llm instance and without auxiliary purpose. Only finish.error with failure.code PI_AI_ERROR and anchored native message `WebSocket closed (1000|1012)`; exclude auth/quota/billing/policy/oversize reasons and 4xx status. Other codes, providers, completions/cancellations, and exceptions remain unchanged.
- Copy only finish/failure to code TRANSPORT, preserving message/metadata and all prior chunks; next called once. No custom buffering/retry, no readonly mutation, no redefinition of adapters, and no core/TUI changes.
- Existing official retry: normal, maxRetries 5, backoff 500ms–10000ms jitter 0.1; do not alter OAuth policy without supported seam. New assistant/attempt in same step/turn, llm/retry audit, and official cancellable waits; tool execution occurs only after successful assistant/message. Do not include generic PI_AI_ERROR in retryableCodes and do not use always/infinity.
- Compaction/title/auxiliary calls do not receive retry from this plugin; summary-error seam is synchronous and will not be used as an improvised loop/backoff. Retains existing 190k configuration.

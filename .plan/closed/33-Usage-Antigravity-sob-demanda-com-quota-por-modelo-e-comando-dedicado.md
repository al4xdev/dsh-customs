# Usage Antigravity sob demanda com quota por modelo e comando dedicado

## Objetivo autorizado
Usuário pediu implementar usage primeiro e só depois decidir recuperação por quota. Goal atual guia implementação após aprovação. Entregar `/antigravity-usage` e serviço host reutilizável que mostrem percentual reportado, reset, idade/stale e janela desconhecida quando não informada. **Nenhuma mudança de retry nesta task.** 429 pode rate-limit/capacidade/quota; não garantir que ocorre antes de quota zero.

## Escopo mínimo
Fork separado `plugins/dsh-antigravity` limpo observado. Source apenas: novo quota/parser e usage/service/formatter (pode consolidar arquivos); DTO em src/types.ts se útil; src/index.ts integra provider manager compartilhado + serviço antiGravityUsage e comandos opcionais via ctx.inject(['commands']) sem tornar comandos dependência obrigatória de inference. Registrar nome dedicado `antigravity-usage` na registry oficial, não substituir /usage/login/provider/model. Aceitar argumento opcional `--refresh` para invalidar TTL/obter fresco; rejeitar demais inputs. Resultado é texto seguro e persistido pela registry (sem LLM turn). Atualizar READMEEN/ZH, testes e inclusão explícita vitest standalone; adicionar peer/type dsh-commands rc2 se import necessário, sem instalar deps ou mudar locks incidentalmente. Config defaults inference/search/retry e model catalogue permanecem iguais.

## Dados e interpretação
MVP usa endpoint existente `/v1internal:fetchAvailableModels` e fields `models[id].quotaInfo.remainingFraction/resetTime`, sem summary endpoint novo ou root window adivinhada. Namespace seguro: fonte, observedAtMs, stale/status/error code allowlisted, rows id/name/fraction?/resetAtMs?/window unknown. Fraction [0,1] finite, zero distinto absent/unknown, invalid não vira0/100. Exibir >0 pequeno como <1% em vez de0%. Reset aceita RFC3339 explícito timezone validado para epoch-ms, invalid unknown; passado mostra passado/precisa atualizar, não inventa now+5h. Não inferir five-hour/weekly de distância até reset, plano ou 429. Não somar variantes potencialmente partilhadas. Display de nomes/ids normalizado/bounded contra controles/ANSI; body/headers/email/project/token/tiers/clientsecret nunca entram DTO/text/log.

## Transporte/lifecycle
Reusar credential manager do provider e endpoint autorizado para metadata, sem inference, onboarding novo, account/model rotation, billing/overage. Consulta futura executada ao usuário invocar comando/service; não adicionar polling/startup calls/quota auto refresh extras. Credenciais OAuth existentes podem ser renovadas pelo manager (renovação pode persistir token): read-only refere-se metadata/quota/billing, não promessa de zero refresh writes.

Fetch limitado (ex10s total incluindo espera de credential), body limite ex1MiB, rows limite ex256, endpoints allowlisted existentes. Preferir helper transporte seguro sem alterar semântica do catálogo/inference; não tomar fallback403/429 como forma de fugir quota (falhar sanitized, fallback só endpoint ausente/indisponível escolhido explicitamente). Error reporting safe codes/status sem error.message bruto. Cache TTL60s, force refresh explícito, single-flight; resultados frescos/imutuáveis detached; stale identificável sem confundir com quota atual. Cancel caller+lifetime, timeout, cleanup/drain; um waiter cancel não cancela outros, todos cancel/dispose abortam transporte. Invalidar cache em credentials/reference-updated/logout e impedir publish de resultados de geração/account antiga; testar refresh OAuth/invalidation race (own token refresh não deve revelar cache de conta anterior). Fonte não dispara leitura secreta na disponibilidade ou registro. Falha usage não derruba inference.

TUI atual pode fornecer signal sem ligação ao botão cancelar: não prometer cancel tecla imediato; deadline próprio garante não esperar horas. Native registry grants/escopo permanecem, sem bypass de permissions.

## Gate obrigatório antes de efeitos
Preflight readonly normaliza destino e congela PreparedIntent com hash de versão+caller/callId+delivery/texto literal+path canonical/nome+IDs host-minted+preset/revisão+modelo+capability/policy generation. Exibir conteúdo exato antes da decisão. Body chama ApprovalService.request native, mesmo se middleware anterior retorna allow. SOMENTE allowed-once chega ao commit; rejected/cancelled/unavailable/never/missing service/late answers dão zero business effects. Não pedir duas aprovações nem reaproveitar grant/token do caller. Logs asked/decided da aprovação são efeito audit legítimo, não sessão/projeto.
Revalidar caller, política, config/preset/model, path realpath/dev/ino e intenção após awaits e antes de cada etapa. Native argumentos são deep-frozen, mas hash/caller também vinculam recuperação. SDK não atesta humano criptograficamente: confiança inclui composição curada/UI legítima sem auto-answerers; não alegar proteção contra plugin host malicioso. Sem adicionar answerer automático.

## Provisionamento e autoridade por projeto
Owner-service HOST/root lifetime, independente do handle parent, usa APENAS APIs públicas para criar Agent/sessão/preset/associar projeto. IDs gerados no host e fresh-only verificado; native create com ID pode adotar existente, portanto nunca usar essa adoção como autoridade. Nenhum TUI open/newSession, sdk-protocol session/prompt lazy ou write em DB/log manual.
Para cumprir projeto novo writable, acrescentar autoridade NARROW por sessão/cwd aprovado, sem alterar comportamento do controller Android nem liberar qualquer cwd. Ledger privado host-owned liga operação aprovada, sessionId/incarnação/header validado, cwd canonical e policy generation; guard só aceita contexto com prova trusted válida, core workspace-write continua limitado a header.cwd e Bash continua ask/allowed-once. Sem prova ou drift, deny writes. Projeto externo não coberto retorna capability unavailable. Parent/legado/IDs reutilizados/sibling e model-supplied workspaceRoot não ganham permissão. Não declarar apenas subdiretório como writable com guard antigo.
Se SDK não permitir esse seam scoped de forma pública/segura, falhar capability antes de aprovação/efeito e registrar dependência/decisão do dono; NÃO substituir por relax global ou API privada. Realpath rechecks não provam fd-pinned proteção contra processo host malicioso; confinar roots controladas e declarar limite.

## Idempotência, falhas e recuperação
Journal privado durável só depois do allowed-once e ANTES do primeiro efeito, com IDs host-minted/intention hash e fases. Mesmo idempotency key com payload diferente é conflito; native requestId dedup não verifica payload. Serializar por operação/destino e fences de epoch, status readonly restrito ao caller. Preservar registros/resultados conhecidos; crash após efeito antes receipt é UNKNOWN, sem retry automático/resume/model.
Output diferencia project/session/submission not_started/confirmed/unknown, IDs, accepted:true/completed:false, retry_safe/recovery_required. Pasta/projeto/sessão podem ficar após falha posterior; default keep-on-failure, nenhuma exclusão/archive/stop automático. Dispose não promete apagar transcript; archive não é rollback de prompt. Recuperação inspeciona readonly; retomar passos exige aprovação fresca.

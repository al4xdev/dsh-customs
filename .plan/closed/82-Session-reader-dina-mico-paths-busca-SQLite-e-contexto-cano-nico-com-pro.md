# Leitura dinâmica de sessões — SQLite para busca, canônico para conteúdo

## Pedido e evidência
Dono pediu em paralelo ao APK8 substituir a leitura difícil atual por lógica SQLite do DSH, com paths e descoberta dinâmica para varrer contexto. Auditoria readonly achou a tool em plugins/session (não companion-workspace). SDK instalado 0.2.0-rc.2 usa JSONL.zstd V4 como fonte canônica. dsh-session-query-sqlite é FTS derivado V8/application_id1146308689, sem eventos estruturais completos; TEMP live pertence à conexão. Companion compõe path:':memory:',openAt:never, sem índice persistente habilitado observado. Loader/search nativos reconciliam/escrevem cache; não chamar isso zero escrituras. Não houve consulta de histórico/DB real.

## Direção e limites
Melhorar a tool session existente sem perder send/resume e suas aprovações. Busca SQLite fornece candidatos, nunca substitui autoridade/conteúdo canônico. Confirmar header/incarnação/revisão e reextrair snippets autorizados redigidos antes de retornar. Não devolver snippet FTS cru, que inclui tool args/results. Não migrar persistência, não usar SQLite legado V17 como se atual. Não modificar SDK, controller global, guards, modelo, TUI, APK8, banco/histórico/perfil ativo ou serviço na implementação.

## Fonte e operações
1. Separar router read-side dos controles existentes, mantendo contratos backward-compatible. help/describe anuncia parâmetros por operação e capacidades efetivas, sem schema amplo opaco.
2. sources/paths descobre configuração pública efetiva e distingue persistenceRoot, project cwd, projectDir, sessionDir, geração física selecionada e SQLite index path/memory/disabled. Resolver symlinks de pacotes; não inferir cwd do encoding lossy de diretório nem root do process.cwd. Não varrer home indiscriminadamente.
3. list/search/context/read aceitam sourceId/pathRef e filtros explícitos de projeto/cwd prefix component-aware/diretório dentro fonte validada. IDs nativos sem restrição ASCII inventada. Busca literal phrase versus substring são modos distintos, sem SQL arbitrário, ATTACH, extensões, shell ou regex ilimitada.
4. Usar public SessionQuery/SQLite provider quando disponível/configurado, com proveniência e freshness conferidas; SQLite externo não vê live TEMP. Fonte canônica JSONL e metadados/live validados preservam contexto recente e live-only. No perfil com índice desativado, reportar capability/coverage e oferecer fallback paginado limitado/cache de cuts, nunca empty como 'tudo varrido'.
5. Preparar configuração/proposta de índice nativo derivado persistente dedicado para ativação posterior se necessário à busca rápida. Nenhum cache real será criado agora. Alternativa em memória pode ser testada/configurável e rotulada derivada, não 'DB canônico'. Native managed indexing pode escrever SOMENTE cache derivado explicitamente configurado, nunca logs; isso deve aparecer nas capacidades. Não usar loader mutante como reader estritamente readonly. Adapter standalone só se provar segurança/source binding; se sidecars/locking não puderem ser garantidos, declarar unavailable em vez de immutable=1 no live.
6. context traz pedido original/head e tail em janelas separadas ou anchor seq/hit, alinhado a mensagens. read preciso preserva seq lógica e paginação de texto redigido, não linhas físicas. Nunca resumir com modelo.

## Consistência, custos e segurança
Cursores ligados a fonte, identidade/incarnação, filtro/ordem/revisão/cut. nextCursor null no fim e pollingCursor separado append-safe. Recriação/rewrite/shrink/geração superior corrupta não reutilizam cut antigo nem fazem fallback silencioso para geração inferior. Retornar coverage, skipped/reasons, freshness, logical/durable/live/synthetic, cut/revision e limites efetivos.
Preservar orçamento output8KiB/default,32KiB max,rows32/100,text512/4096 como ponto inicial; scans resumíveis com orçamento de candidatos/bytes/eventos/tempo, progresso mesmo com linha omitida. Trabalho backend não é limitado só pelo output: evitar tail108 decodes usando native observation cuts/cache bounded quando possível; isolar trabalho síncrono e cancelamento, sem alegar hardRAM cap que binding não oferece. Cache só bounded/current source revision; nenhuma transcript no cache de navegação.
Redaction não é DLP perfeito: preservar política atual de conteúdo permitido, excluir reasoning/tool payloads/anexos do default, validar texto autorizado mesmo em assistant misto e aplicar redaction ANTES snippet/corte. Caminho descoberto não é grant nem prova de existência atual.

## Ownership e validação

Testes sintéticos de sources/path roles/encoding collisions/dupIDs, SQLite native V8 versus foreign/V17 sem reset, disabled fallback, freshness/store swap/live overlay, phrase/substr/emoji/filters, original request/context, redaction boundaries, cursor tamper/incarnação/append/rewrite, budgets/cancellation e counters decode/cache/tail. Runtime SDK só home/store/DB authored isolados, provider dispatch proibido; nenhum modelo/Agent real.

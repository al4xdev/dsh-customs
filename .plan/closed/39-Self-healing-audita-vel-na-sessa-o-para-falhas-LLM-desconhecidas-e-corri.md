# Self-healing auditável na sessão para falhas LLM desconhecidas e corrigíveis

## Pedido e goal
Usuário explicitamente diferencia agente de chamada LLM síncrona: retry automático resolve causas óbvias; falha complicada deve virar observação de erro na própria sessão para o agente analisar/reparar/continuar, com histórico para auditoria. Consumir cota de assinatura está autorizado. Reusar goal4132625b revisão5 armado; não criar objetivo paralelo. Tasks36/38 permanecem independentes, source/candidatos congelados e promoção apenas com recibos; este task não faz chamadas reais nem habilita créditos.

## Seam público comprovado
Host dsh-agent-loop settle da tentativa falhada acontece antes de agent/request-error e antes de dispatch CLIENT. Action retry reconstrói prepareRequest/llm.prepareCall e rederiva session.deriveMessages em cada tentativa. Assembly/tools/renderedPrompt da decisão original não são reconstruídos; portanto não prometer que o modelo consegue consertar um schema rejeitado antes de qualquer inferência. agent.steer/inject enfileiram next-step, não atendem retry no mesmo step. followup após agent/error chega depois do goal-driver desarmar activation.

## Fase1 implementável sem editar host
1. Novo plugin root de self-healing, com nome/config/documentação próprios, independente de providers. Usar middleware público agent/request-error; await next primeiro para deixar retry transitório oficial decidir. Não criar motor de retry/Always. Se houve ação, retornar intacta. Se não houve, tratar apenas falha normal de agent-loop elegível, signal vivo, erro tipado validado, sem colisão de controller/Goal cancel. Scope agentes normais; title/compaction/ordinary/sdk direct não entram.
2. Preferência para PI_AI_ERROR desconhecido e EMPTY_RESPONSE repetido após retry oficial, e INVALID_REQUEST apenas se diagnóstico próprio comprovar schema/opção corrigível, não em bloco. ABORTED, AUTH/billing/QUOTA_EXCEEDED, contexto excedido já tratado pelo driver, política/conteúdo bloqueado e falta de consentimento não recebem blind replay nem instrução para contornar. Não alterar conta/modelo/credenciais/rotas/credits/privileges. O agente pode explicar uma condição externa; isso não é licença para bypass.
3. Extender MessageSourceMap com kind interno self-heal-observation e ContextFormed notice, sem se passar por usuário real/system-prompt/tool/model/goal. Extender SessionEventMap com eventos auditáveis recovery para decisão, observação admitida, reparo solicitado/recuperado/esgotado. session.append(user/message,createUserMessage(...),{surfaceOp:'append'}) usa seam público compatível com producer sintético; anexar mensagem somente após failure settlement e antes de retornar {kind:'retry'}. Ordem audit + message + retry explícita, sem multi-eventatomic claim, falha parcial não autoriza replay/repetir efeitos. Abort entre etapas registrado e não retry.
4. Observação contém dados estruturados e aviso de contexto: code/status/hints, provider/model conhecidos, turn/step/cycle, uso/cap de saída quando disponíveis, fase/categoria conhecidas e diagnóstico seguro. Erro remoto é dado não confiável, nunca comando ou identidade de autoridade. Nunca incluir raw request/response/header/cause/stack, pensamento oculto, tokens, chaves, cookies, email/account/project ou URLs com query. Mensagens fixas produzidas pelos bridges próprios podem ser preservadas; desconhecidas não são universalmente sanitizadas: selecionar apenas fatos seguros e summary fixo, ou diagnóstico extraído explicitamente por parser de formatos públicos com testes de canary. Não alegar regex de redação garantia universal. Não ler credenciais reais para redigir logs.

O user/message recovery muda contentGeneration/startSeries; NÃO usar esses valores para resetar budget. Reset só por progresso/turn saudável comprovado. Rebuild/plugin reload/replay não reinicia budget. Dedupe eventos observação/append parcial via chain+cycle e causal eventseq; evitar dupla admissão quando callbacks concorrem. Audit local/session persistente, sem segredos, com campos allowlist e volume limitado. Sourceerror não define nomes de caminhos/ações.

Registrar suspensão e permitir terminação atual conhecida; goal durable continua ativo mas activation pode ser desarmada pelo driver. Documentar que isso é checkpoint recuperável/manual resume, não implementação de autoagendamento. Só usar public goals.pause com exactref se seu lifecycle não rotular cancel automático como humano e fixtures provarem autorização; caso contrário não chamar pause interno. Não rearmar automaticamente goal pausado por pessoa, não enfileirar nova rodada após dispose/cancel. Futuro wait/reschedule precisa fase2 aprovada.
7. Reparos permitidos são reflexão do modelo e ações normais já autorizadas; plugin não executa comandos de log e não concede permissões novas. Erro tool/result já entra no histórico normal e não dispara replay de ferramentas. ## Limites/Fase2 não autorizada por este artifact
Thrown prepareCall/stream-consumer/settlement exceptions podem escapar agent/request-error e atingir agent/error emit-only. Não converter business-consumer exception em TRANSIENT nem manipular runtime private state. Novos host recovery action/assembly rebuild/lifecycle suspend+resume e neutralização segura de callback fault precisam artifact separado baseado no contrato, sem prometer cobertura universal neste primeiro plugin. Caso a fase1 não satisfaça um cenário essencial do usuário, relatar seamfaltante e proporfase2, não esconder erro nem marcar objetivo integral completo.

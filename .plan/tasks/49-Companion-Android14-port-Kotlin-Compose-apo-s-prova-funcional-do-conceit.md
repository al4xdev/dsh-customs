# Companion Android 14 — Kotlin/Compose/Material 3

## Precondition and Objective
Use active goal to guide the native phase. Technical proof of concept was completed in tasks 40/45/47: published frontend, native confirmation, authentication, history/reconnection, real tool, and comprehensive discovery across 880 sessions with separate control writer. Explicit limitation: existing terminals without bridge do not receive messages; do not restart them or hot-inject modules.

Port Companion CLIENT to native Kotlin, exclusively Android 14 / API 34, with Jetpack Compose and Material 3. Do not invest in React/animations. DSH / observation backend remains on the PC, as it observes/controls that PC's sessions; do not claim DSH/LLM engine runs on Android. The simplification goal is eliminating the need for separate React frontend/proxy once native client is validated.

## Steps
1. Audit available Android/JDK/Gradle/SDK 34 environment without reading/exposing keys from other apps, installing APK on phone, or altering existing projects. Inspect public DSH 0.2.0-rc.2 contracts: auth, RPC, remote.mux, retention/follow/page/projections, queue/cancel, and approval. Map strict Kotlin DTOs and limits; no message guessing or dependence on private internals.
2. Resolve companion-exclusive listing before retaining chats: native summary does not contain agentPreset. Prefer a small host extension solely on companion backend, using public remotes/auth APIs and sessionPersistence.list/stat to return validated metadata, reusing logic / catalog guards. No new daemon, arbitrary backend, global tool registry, fictitious RPC firewall, or editing installed runtime. If no adequate authenticated public seam exists, document and keep current proxy until safe alternative; do not publish open endpoint.
3. Create dedicated Android project, e.g. `android/companion`, exclusive package. minSdk 34 / targetSdk 34, Kotlin/Compose/Material 3, reproducible build and proper lint/tests. No WebView, iframe, React renderer, TUI fork, or dependency on CasaTequila app. Reuse DSH contracts/semantics, do not claim reuse of React renderer in Compose.
4. Minimal UI list/chat, New, Back, connection state, composer/send/cancel, paginated history, and streaming response. No profile/model selection, DSH settings, or editor/terminal. Markdown/code/tables and tool results with safe textual fallback. Motion limited to Material/OS defaults, no new premium investment.
5. HTTPS authentication against fixed proprietary origin, startup token kept solely in memory during login, validated redirects and cookies, no logs/interceptors/HAR/clipboard/build secrets. Persist cookie only if needed in encrypted storage via Android Keystore; do not store startup token. Standard TLS, no trust-all or bypass. No attaching personal browser profile.
6. Create/open/retain companion chats only after header/preset proof and revalidate race conditions / deep links. Preserve authenticated OWNER API and trust caveats. Selecting another session to observe/send remains the `session` tool within chat, not mounting standard agents via the app.
7. Native approvals: display literal target/action/text, Reject/Allow once, waiting state, and idempotent responses. Never auto-approve, decide on behalf of user, conflate ACK with completed execution, or repeat unknown result. Log data is untrusted text.
8. Test parser/protocol with synthetic fixtures and real read-only NativeAPI; errors/timeouts/reauth, streaming order/replay, pagination, reload/reconnect, selection/copy, Android 14 keyboard/insets, approval/rejection only with synthetic target. SDK/API 34 emulator if available; do not claim physical testing if not performed. Do not install/launch apps on personal phone without specific confirmation.
9. Generate test APK, inspect package/minSdk/targetSdk, and deliver existing file via `present`. Do not reuse signing keys from another app. Document usage/login/limits and keep Web/TUI/proxy working as rollback. Only disable frontend 3082 or move 8443->3081 after APK validation and corresponding publishing authorization; do not alter 443/3080 or third-party profiles/models/histories.

## Acceptance Criteria
Native APK compiled/checked for API 34 with secure list/chat/streaming/history/confirmations and real evidence or explicitly reported limits. Single backend on PC, no additional frontend daemon required in validated final architecture. Existing Web/TUI and companion policies preserved; no secrets in code/artifacts/logs, no sends to real sessions for testing, no takeover. No commit/push.
